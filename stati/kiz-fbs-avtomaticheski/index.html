Честный знак на Озон FBS: как привязывать КИЗ к заказам на объёме

Честный знак на Озон FBS — это две отдельные работы. Первая: привязать КИЗ (контрольный идентификационный знак, код DataMatrix из «Честного знака») к каждому отправлению. Вторая: самому вывести проданные коды из оборота, потому что на FBS товар до покупателя принадлежит вам. Пока заказов десятки, это делают руками в кабинете. Когда их сотни и тысячи, привязку переносят в API: у Ozon и Wildberries есть методы, которые принимают коды по номеру отправления. Скрипт делает это прямо в момент сканирования на упаковке.

Коротко

  • На FBS коды из оборота выводит продавец как собственник товара, а не маркетплейс. Причина в документе — «Дистанционная продажа» («Честный знак»).
  • У Ozon коды к отправлению передаёт метод /v6/fbs/posting/product/exemplar/set. Старые версии v4 и v5 Ozon удалил из документации 13 января 2026 года (канал Ozon Seller API).
  • У WB код привязывают методом PUT /api/v3/orders/{orderId}/meta/sgtin. Без программиста — массово через XLSX-шаблон в кабинете (WB).
  • Ошибка «неверный формат» (у WB — «Неподходящий формат») чаще всего значит, что сканер потерял невидимые разделители GS внутри кода.
  • Вывести коды из оборота можно файлом CSV или XML через раздел «Документы» в личном кабинете «Честного знака».

Кто что делает на FBS: Ozon, WB и вы

На FBS товар лежит у вас, и маркетплейс не участвует в обороте кодов. Так прямо пишет «Честный знак»: вывод из оборота делает собственник товара, а не логистическая компания. Делать это нужно при отгрузке со склада для доставки покупателю, до дня фактической доставки.

WB в инструкции по FBS пишет то же самое: вывод из оборота идёт вместе с фактической отгрузкой, выводить КИЗ нужно самостоятельно, а при возврате товара код надо вернуть в оборот (инструкция WB, правка 02.10.2026).

Подробнее о том, какие товары вообще маркировать, — в статье «Честный знак на маркетплейсе». Про саму схему FBS у Ozon — «FBS Озон: схема, комиссия и сроки».

Привязка КИЗ к заказу Озон автоматически: что умеет API

API — это способ, которым программа сама работает с кабинетом без человека в браузере. Для селлера это значит: код уходит в заказ в ту же секунду, когда кладовщик его отсканировал. Никакого Excel «номер задания — КИЗ» и никакой ручной сверки в конце смены.

Актуальные методы Ozon для кодов маркировки FBS по официальному каналу обновлений Ozon Seller API (на октябрь 2026):

  1. /v3/posting/fbs/unfulfilled/list — список необработанных отправлений. С марта 2025 года в ответе есть блок products_with_possible_mandatory_mark: в нём товары, которым может понадобиться маркировка.
  2. /v6/fbs/posting/product/exemplar/create-or-get — получить идентификаторы экземпляров (exemplar_id) в отправлении.
  3. /v5/fbs/posting/product/exemplar/validate — проверить коды до передачи.
  4. /v6/fbs/posting/product/exemplar/set — передать коды. С 5 февраля 2026 года обязательны номер отправления, product_id и exemplar_id.
  5. /v5/fbs/posting/product/exemplar/status — узнать статус проверки каждого кода.
  6. /v3/posting/fbs/get с параметром with.product_exemplars: true — посмотреть, какие коды уже стоят в отправлении.

Если ваш интегратор писал скрипт до 2026 года на /v4/.../exemplar/set или /v5/.../exemplar/set, проверьте его. Эти методы Ozon пометил устаревшими и убрал из документации 13 января 2026 года.

Два подводных камня из чатов разработчиков:

  • Одного set мало. В чатах советуют после привязки кодов отдельно вызвать сборку отправления (/v4/posting/fbs/ship). Иначе заказ не уходит в статус «ожидает отгрузки».
  • Стикер появляется позже, чем код. Селлер, который подключал привязку на своём складе, пишет: через API этикетка доступна только в статусе awaiting_deliver, а КИЗ он привязывает ещё в awaiting_packaging. Поэтому сценарий «отсканировал стикер, потом код» на Ozon в лоб не работает: коды привязывают по номеру отправления, этикетки печатают потом. Официально база знаний Ozon разрешает передавать коды на FBS до передачи отправления в логистику, пока оно в статусах «Ожидает сборки» и «Готов к отгрузке». Как это работает в вашей связке методов, проверьте на тестовом заказе.

У WB всё проще. Метод PUT /api/v3/orders/{orderId}/meta/sgtin закрепляет коды «Честного знака» за сборочным заданием, если задание в статусе confirm («На сборке»). Получить уже привязанные коды можно методом POST /api/marketplace/v3/orders/meta, удалить ошибочные — DELETE /api/v3/orders/{orderId}/meta (WB API, заказы FBS). Подробнее про токены — в статье «API Озон и WB для селлера».

Сканирование честного знака на ФБС Озон: откуда «неверный формат»

КИЗ состоит из четырёх частей: GTIN после тега 01, серийный номер после 21, ключ проверки после 91 и криптохвост после 92 или 93. Между частями стоят служебные символы GS. Глазом их не видно, но без них код может не пройти проверку. В кабинете WB такая ошибка называется «Неподходящий формат» (инструкция WB, правка 02.10.2026).

Что из этого следует на практике:

  • Не копируйте код из Excel или документов. Разделители теряются при копировании. WB прямо советует сканировать DataMatrix с этикетки.
  • Включите в сканере передачу GS. У разных моделей пункт меню называется F8 Mode, Alt+0029 Mode или GS1 Enable. По инструкции WB, сканер может передавать GS клавишей F8 или комбинацией Alt+0029.
  • Нужен 2D-сканер. WB пишет, что подойдёт любой сканер, который читает 1D- и 2D-коды.
  • Для скрипта через API разделитель передают символом \u001d. В чатах селлеров его советуют ставить перед блоками 91 и 92, если код пришёл без него.

Что именно Ozon принимает в поле кода через сканер в кабинете, в официальной справке я не нашёл. Если код не проходит — уточните в базе знаний Ozon.

Печать стикера ВБ с КИЗом: что есть в кабинете

Этот вопрос в чатах звучит так: «можно ли напечатать стикеры WB с привязанными КИЗами, чтобы на принтере выходили друг за другом стикер задания, затем честный знак?». По инструкции WB, в кабинете четыре вида стикеров для FBS: стикер заказа, стикер баркода, артикул для подбора и данные о поставке. Стикера «заказ + КИЗ» среди них нет (WB). Этикетку с КИЗ вы печатаете из «Честного знака» или своей программы маркировки. WB советует размер DataMatrix 22 × 22 мм и чёрный цвет.

Что можно сделать штатно:

  • Печатать стикеры с фильтрами листа подбора — например, сначала только заказы с фильтром «Нужна маркировка».
  • Добавлять КИЗ сканером прямо в интерактивном листе подбора. Отсканировали стикер WB, отсканировали код, система сохранила и сама отправила его на проверку (лист подбора WB).

Чтобы стикер задания и этикетка КИЗ выходили из принтера парой, нужен скрипт. Он берёт стикеры заданий по API (POST /api/v3/orders/stickers), коды из своего пула и склеивает их в один файл для печати.

Вывод КИЗов из оборота файлом

Когда отгрузок много, выводить коды по одному не нужно. По инструкции «Честного знака» документ «Вывод из оборота» подают файлом:

  1. Шаблон CSV или XML лежит в разделе «Помощь» личного кабинета системы маркировки.
  2. Заполните файл, не меняя расширение. В CSV каждый код берут в двойные кавычки, а кавычки внутри кода удваивают.
  3. Войдите в кабинет с УКЭП (квалифицированной электронной подписью), откройте «Документы» → «Загрузить» → «Вывод из оборота».
  4. Проверьте предпросмотр и нажмите «Подписать и отправить». Успех — статус «Обработан успешно», коды переходят в «Выбыл».

Инструкция опубликована в разделе «Честного знака» про молочную продукцию. Для вашей товарной группы порядок может отличаться — проверьте раздел «Помощь» в своём кабинете. Для программной интеграции у «Честного знака» есть свой API — True API. Его описание тоже лежит в «Помощи» личного кабинета.

Где взять список кодов. У Ozon есть отчёт «Продажи маркированных товаров». Селлеры в чатах пишут, что в нём есть дата, КИЗ и номер чека, но нет суммы. Где он лежит в кабинете сейчас — уточните в базе знаний Ozon. У WB селлеры берут коды из выгрузок сборочных заданий на вкладках «Завершённые» и «Отменённые».

Когда выводить. Здесь первоисточники и чаты расходятся. «Честный знак» пишет: при отгрузке, до дня фактической доставки. WB — вместе с фактической отгрузкой. В чатах чаще советуют выводить после выкупа, в течение трёх дней, чтобы не возвращать код в оборот при отказе. Эксперт «Клерка» со ссылкой на рекомендацию Ozon тоже говорит про статус «Доставлен». Ориентируйтесь на правила своей товарной группы в «Честном знаке», а не на совет из чата.

Что спрашивают про КИЗ на FBS в чатах селлеров

Мы читаем больше 200 Telegram-чатов селлеров WB и Ozon. С 22 сентября по 18 октября 2026 года там задали около сотни разных вопросов про КИЗ и «Честный знак» на FBS. Чаще всего спрашивали:

  • про вывод и возврат кодов в оборот — около четверти вопросов: когда выводить, где взять список, нужна ли цена;
  • про сканирование при сборке;
  • про отказы и возвраты: куда едет товар и что делать с кодом;
  • про API и автоматизацию;
  • про ошибки проверки и формата.

Три боли, которые повторяются.

  1. Масштаб. «У нас могут быть тысячи на сборке у одного сотрудника». Или: «по 5000 отправлений в день — как это сделать быстро и не руками». На таком объёме ручной ввод в кабинете не справляется.
  2. Потерянная связь «код — заказ». «200 баночек одной партии, у каждой свой КИЗ, сводим номера заданий и коды в Экселе. Кто как понимает, какой код ушёл в какой заказ?» И следом: «по старым ФБС-заказам часть КИЗов вообще не найти».
  3. Интерфейс Ozon меняется. За две недели в чатах успели написать, что Ozon убрал поле КИЗ при сборке, что вернул его, что маркировка «необязательна» и что её вдруг требуют по всем заказам. Что обязательно для вашего товара сейчас — смотрите в кабинете и базе знаний Ozon.

Отдельно про WB в чатах уточняют последствия. Если не указать КИЗ в задании и покупатель откажется, товар вернётся в ваш ПВЗ, а не на склад WB. Это подтверждает и инструкция WB: такой возврат платный.

Автоматизация КИЗ на FBS: что сделает скрипт и ИИ

Я собираю ИИ-агентов на Claude и подключаю ИИ к кабинету Ozon через API. Схема для FBS с маркировкой, которую я бы собирал, выглядит так.

  • Место упаковки. Кладовщик сканирует номер отправления, потом DataMatrix на товаре. Скрипт сразу шлёт код в Ozon (exemplar/set) или WB (meta/sgtin) и показывает зелёный или красный экран. Ошибка видна сразу, а не через неделю.
  • Журнал «заказ — код». Каждая привязка пишется в таблицу. Через месяц вы за секунду найдёте, какой код ушёл в какой заказ.
  • Ежедневный вывод из оборота. Скрипт собирает коды проданных отправлений и готовит CSV по шаблону «Честного знака». Подписывает и отправляет человек со своей УКЭП.
  • Возвраты. Список вернувшихся отправлений с кодами — для документа о возврате в оборот.

Где здесь ИИ. Нейросеть не сканирует и не решает, какой код в какой заказ, — это делает сканер. Зато ИИ-агент пишет такой скрипт по описанию задачи, читает ошибки API вроде пустого ответа {} и объясняет, что пошло не так, а ещё сверяет отчёт Ozon с журналом и находит коды, которые забыли вывести. Без программиста на WB хватит XLSX-шаблона в кабинете. На Ozon при больших объёмах без API или готового сервиса маркировки не обойтись.

Чего автоматизация не сделает: не напечатает КИЗ, которого нет, не подпишет документ в «Честном знаке» вместо вас и не исправит ТН ВЭД в карточке. Про ТН ВЭД и проверку кодов на WB — в статье «КИЗы Вайлдберриз».

Частые вопросы

Кто выводит КИЗ из оборота при FBS на Озоне? Продавец, как собственник товара, в «Честном знаке» с причиной «Дистанционная продажа». На FBO это делает маркетплейс, на FBS — вы.

Можно ли загрузить КИЗы в FBS-заказы не вручную? Да. На WB — XLSX-шаблоном в поставке или через API meta/sgtin. На Ozon — через API /v6/fbs/posting/product/exemplar/set.

Почему при сканировании КИЗа пишет «неверный формат»? Чаще всего сканер не передаёт невидимые разделители GS. У WB эта ошибка называется «Неподходящий формат». Включите в настройках F8 Mode, Alt+0029 Mode или GS1 Enable и не копируйте коды из Excel.

Передаём коды через exemplar/set, а в ответ пустые скобки {}. Что не так? В чатах советуют проверить статус кода методом /v5/fbs/posting/product/exemplar/status, а после привязки вызвать сборку отправления. Отдельно проверьте, что в коде есть разделители GS.

Что будет, если на WB отправить FBS-заказ без указанного КИЗ? По инструкции WB, товар уедет покупателю без проверки кода. При отказе или возврате он вернётся в ваш ПВЗ, а не на склад WB, и возврат будет платным.

Отказ покупателя на FBS — что делать с кодом? Если код уже выведен — вернуть его в оборот в «Честном знаке». По инструкции WB, после повторной проверки такой товар можно снова продавать.
